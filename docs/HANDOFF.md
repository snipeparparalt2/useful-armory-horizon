# Useful Armory 0.1.7: handoff

Paste this whole file to the agent taking over. It is self-contained.

## What this project is

Useful Armory is a mod for **Horizon**, a Rust rewrite of Minecraft: Java Edition
(https://github.com/horizon-rust/horizon). Target: Horizon commit
`fdc87aecdbd116bf1e08adcd062fcbaea8c2e2ca` (Nightly 2026-11-08), game data 26.3.

- Repo: https://github.com/snipeparparalt2/useful-armory-horizon
- `main` is the last published version, content **0.1.6**.
- All work in progress is on branch **`update-0.1.7`**. Work there. Do not push to `main`
  until the owner has tested the finished 0.1.7 in game.
- The mod has two halves with the same id, `useful_armory`:
  - **Content mod** (`content/`, packed as `.hmod`): items, blocks, recipes, loot, structures,
    worldgen. Data only. Goes in the game's `horizon-mods/` folder.
  - **Native mod** (`native/useful_armory/`, packed as `.hnmod`): Rust that the Horizon
    launcher compiles into the game (a horizon-mixins bundle). Goes in `horizon-native-mods/`.
    Never put the `.hmod` there: the launcher's Build fails with "missing horizon-native.json".

## The owner's decisions (do not reopen these)

- Everything below ships as **one update, 0.1.7**, in **one drop at the end**. Only the finished
  build goes to GitHub `main` and the Horizon mod browser.
- It must be a real, working, publishable mod. High-end: emissive textures where they fit,
  detailed buildings, no placeholder art.
- Ores sit in **stone** (and deepslate), drawn as a mineral overlay over the game's own stone
  texture. Never copy vanilla textures or other mods' assets into the mod.
- No big crafting table. Leftovers from the original 1.12.2 mod can be removed.
- Buildings are script-generated, big and detailed. The vault and crypt have surface entrances.
  Every chest and barrel has loot.
- Ideas may be borrowed from Java mods, but everything is rebuilt from scratch with our own
  names, code and art.
- Update GitHub with every large release.
- Usage: use the strongest model for art and detailed design, a mid model for code, a small
  model for small data files and docs.

## Done so far on `update-0.1.7`

**Phase 1, places (content).** Generated by `tools/gen_phase1.py` from one module per place in
`tools/structures/`, using the toolkit `tools/structkit.py`. Design brief:
`docs/design/places.md`.
- Twelve places: ruined forge, wanderer's camp, aquite shrine, colosifite watchtower, bandit
  fort, village armory blacksmith (added to five village house pools), pigman outpost (Nether),
  shadow vault (surface mausoleum and spiral stair down), miner's cache, forgotten armory,
  infested mine, crypt dungeon (multi-piece jigsaw with a surface mausoleum entrance).
- 14 chest loot tables (`chests/<place>`, `chests/crypt_treasure`, `chests/supplies` for
  furniture containers), six loot-only relic items, two zombie-based guardian mob types
  (`vault_guardian`, `tower_sentry`) used in spawners, deepslate versions of the three ores.

**Phase 2, gear that does things (native).** In `native/useful_armory/mixins/useful_armory/`
(`runtime.rs` pure logic with unit tests, `gear.rs`, `glue.rs`, one small file per hook).
Tooltips are added to item JSON by `tools/gen_phase2.py`.
- Coloured glow light from glowing gear (held, worn, dropped).
- Full-set armour bonuses: Aquite water breathing and dolphin's grace; Colosifite fire
  resistance; Emerald luck; Lapis +25% experience; Obsidian half knockback and half explosion
  damage; Quartz speed; Redstone haste; Shadow night vision; Ultimate slow regeneration and no
  fall damage.
- Tool abilities while sneaking: vein mining (colosifite, emerald, shadow pickaxes), 3x3 wide
  dig (obsidian pickaxe and shovel), tree felling (aquite, emerald, shadow axes). Harvest sweep
  with any hoe (3x3) and the reaper scythe (5x5).
- Weapon effects: dagger backstab, greatsword splash, halberd +1 reach (data), magma sword
  fire, soul eater heal on kill, pigman sword bonus against piglin kinds, nether's legacy bonus
  in the Nether, reaper scythe head drops.
- A settings page under Options > Mods with a switch per feature.
- Known gaps: the Shadow set's "mobs notice you from half the distance" is not possible with
  the hooks at this commit. Lapis experience applies to every orb, not only kills and mining.

**Checked:** block states validated against the game's own block list; build is deterministic;
`cargo horizon-mod check` accepts both packages; the native bundle applies with horizon-mixins
and the patched game passes `cargo check` with warnings denied; 21 native unit tests pass; the
crypt was simulated against Horizon's jigsaw rules (400 layouts, each with one treasure room).

**Never seen in a running game:** everything after 0.1.6. See "Before release" below.

## How to work in the repo

```sh
python3 tools/gen_phase1.py --schema <block_schema.json>   # structures, loot, relics, ores, mobs
python3 tools/gen_phase2.py                                # ability tooltips on items
python3 tools/package.py                                   # dist/useful_armory-0.1.7.hmod and .hnmod
python3 tools/item_list.py                                 # docs/items.md
python3 tools/dev/preview_place.py <module> --out DIR --schema <block_schema.json>   # build and render one place
(cd native/useful_armory && cargo test)                    # native logic
```

- `block_schema.json` is not in the repo (it is game data). It maps every block id to its
  state properties, extracted from the game's cache file `model-states.json` under
  `.horizon-cache/mod-content/<hash>/`. On the owner's PC a copy is at
  `C:\Users\thepa\.codex\.chatgpt-projects\g-p-6ad1727bf06c8191b4ebf2ad7f490e94\work\useful-armory-port\.claude-scratch\block_schema.json`.
  Without `--schema` the generator still runs but does not validate block states.
- `tools/gen_phase1.py` deletes and rewrites `content/data/useful_armory/structure/`, the
  `worldgen/structure*`, `worldgen/template_pool` trees and the `has_structure` biome tags.
  Never run two copies at once. When several agents work on buildings in parallel, each edits
  only its own `tools/structures/<name>.py` and uses `preview_place.py`.
- Texture folders must be `textures/item/` and `textures/block/`. Model parents need the
  `minecraft:` prefix.
- `tools/gen_textures.py` no longer reproduces the three ore textures; do not regenerate over
  them.
- Checking the native half against the real game: get Horizon's source at the pinned commit,
  apply the bundle with `horizon-mixins apply --workspace <src> --mods <dir> --out <dir>`
  (horizon-mixins commit `e8cd0aa38cffef49cb2e088ef716baa107148c02`), then
  `RUSTFLAGS="-D warnings" cargo check --locked -p horizon-client --bin horizon-client` in the
  output tree. Horizon's `docs/native-mods.md`, `docs/mods.md` and `native-hooks.json` document
  the hook points. Horizon's own packager check is
  `cargo horizon-mod check <file>` (crate `cargo-horizon-mod` in the Horizon repo).
- Horizon facts that the docs bury: structure JSON shapes are shown by the test
  `content_root_carries_a_structure_mod` in `crates/horizon-client/src/mod_content_tests.rs`;
  structure `.nbt` uses `DataVersion` 5023; jigsaw rules are summarised at the top of
  `tools/structures/crypt.py`; entity types as data accept the templates `minecraft:zombie`,
  `minecraft:villager`, `minecraft:wandering_trader`; `add_spawns` biome modifiers are read;
  custom AI goals go through `native_register_goals`; the launcher builds native code only from
  `.hnmod` files.
